# Agentic IDE 业务设计文档

> 版本:v0.1(2026-10-30)· 状态:待评审
> 本文档描述「做什么」与业务规则,不绑定技术栈;选型见 `design/tech-stack.md`,交互基线见 `prototype/index.html`(已冻结原型)。
> 术语:产品代号 **JIDE**;「用户」指使用 JIDE 的开发者,「agent」指内嵌的 pi 内核会话。

---

## 1. 产品定位

**一句话**:一个把「改完自己测、测完自己验」做成默认动作的轻量 Agentic IDE——agent 在隔离工作区里干活,自测闭环 + 记忆系统让它越用越懂你的项目。

**目标用户**:
1. **独立/小团队开发者**(主力):要 AI 干活,但没有 QA 帮忙验收;最痛「agent 说改好了,其实跑不起来」。
2. **前端/全栈工程师**:改完必须开浏览器点一遍;希望 agent 也能「点一遍」并把结果给自己复看。
3. **AI 重度用户**:受够了每次新会话都重新交代项目约定;要长期记忆,但不要云端账号。

**三大支柱**:

| 支柱 | 一句话 | 反例(没有它会怎样) |
|---|---|---|
| 隔离工作区 | agent 的每次任务在独立 worktree 里进行,计划步骤自动提交,主分支永远可发布 | agent 直接在主分支上改坏,回滚靠翻 reflog |
| 自测闭环 | 改动 → 智能选测 → 浏览器实操验证 → 检查项沉淀,agent 自己先验收 | 「已修复 ✓」但一跑就崩,人肉当 QA |
| 记忆系统 | 文件式项目记忆 + 建议卡片,三级注入约 2K token,越用越准 | 每个会话都从零认识项目,反复踩同样的坑 |

**对位表**:

| 维度 | VS Code | Cursor | GitHub Copilot | ThinkRail | **JIDE** |
|---|---|---|---|---|---|
| 定位 | 通用编辑器 | AI 优先编辑器 | 助手插件 | 极简 agentic IDE | **自测闭环优先的 agentic IDE** |
| agent 改动隔离 | ✗(分支靠自觉) | △ | ✗ | ✓ worktree | ✓ worktree + 步骤自动提交 |
| 测试自验 | ✗ | △(agent 可跑命令) | ✗ | △ | ✓ 选测+浏览器+检查项,**差异化** |
| 记忆 | ✗ | △ Rules | ✗ | ✗ | ✓ 文件式+建议卡片,**差异化** |
| 轻量 | 中(插件膨胀) | 重 | 轻 | 轻 | 轻(单位数 MB 安装包) |

## 2. 核心业务域总览

七个业务域;括号内为主要落地里程碑(M1–M4 见第 9 章)。

```
┌─ ①工作区(M1/M2)──信任门、worktree、上下文原子切换
├─ ②Agent 会话(M1)──pi 会话、对话=内容区页签、上下文芯片
├─ ③测试(M3)──────dev server / 选测 / 浏览器自动化 / 检查项 ★核心
├─ ④记忆(M4)──────建议卡片 / 三级注入 / 整理遗忘 ★核心
├─ ⑤编辑与 Git(M2)──代码编辑、diff 双全文、提交记录、顶栏 Git 状态条
├─ ⑥终端(M2)──────分组终端、错误一键问 agent
└─ ⑦计划与评审(M2/M3)─计划步骤、自动提交、评审队列人工门禁
```

| 域 | M1 | M2 | M3 | M4 |
|---|---|---|---|---|
| ①工作区 | 骨架 | 完整(信任门/切换) | — | — |
| ②会话 | 跑通 | 页签化 | 三档联动 | 记忆注入 |
| ③测试 | — | — | 全量 | 检查项资产化 |
| ④记忆 | — | — | — | 全量 |
| ⑤编辑/Git | — | 基面 | diff 联动 | — |
| ⑥终端 | — | 基面 | 错误问 agent | — |
| ⑦计划/评审 | — | 计划面板 | 评审队列 | — |

## 3. 工作区模型

**实体关系**:

```
Project(信任与配置根,= 一个 git 仓库)
 ├─ Workspace A: Default(main 分支)
 ├─ Workspace B: feat/xxx(独立 worktree)── 会话组 / 终端组 / dev server(:端口N)
 └─ Workspace C: ……
每个 Workspace:计划(可选,一个进行中)· 评审队列(0..n 待审项)
```

**六条业务规则**:

| # | 规则 | 说明 |
|---|---|---|
| W1 | **信任门**:Project 首次打开必须显式信任 | 未信任前:只读浏览;禁止命令执行、文件写入、agent 工具调用 |
| W2 | **Default 工作区**:唯一,绑定主分支 | 用户自己干活的地方;**禁止**计划步骤自动提交 |
| W3 | **隔离工作区**:从任意分支/commit 创建 worktree | 面向 agent 任务;创建即复制工作区上下文(会话模板、检查项、记忆引用) |
| W4 | **上下文独享与原子切换**:会话/终端/dev server 随工作区走 | 切换 = 整套上下文换入换出;dev server 各占端口,互不干扰 |
| W5 | **步骤自动提交**:仅隔离工作区,计划每完成一步自动 commit | 提交信息 = 步骤描述;入口统一进评审队列,**不直接进主线** |
| W6 | **人工门禁**:隔离工作区产出经评审队列「通过」后方可并入主线 | 通过=快进/rebase 合并;追问=带上下文回聊;忽略=留档不合并 |

## 4. 测试域(差异化核心)

**设计原则**:①agent 必须能「自己跑起来看」;②验证结果要沉淀为项目资产而非一次性输出;③人侧与 agent 侧共用同一套引擎(不各跑一份);④一切验证可复看(截图/录屏/日志留档)。

### 4A. dev server 管理
- 工作区持有 dev server 生命周期:启动、就绪探测、崩溃感知、停止;agent 与内嵌预览共享同一实例(共引擎)。
- **就绪探测三模式**:HTTP 轮询( GET / 等 2xx )、端口连通、日志特征(如 "ready in");自动选择,可手动钉死。
- 崩溃感知:进程退出/端口失联 → 状态栏变黄、agent 收到事件可自行重启。

### 4B. HTTP 探测
- 提供轻量探针工具:URL + 期望(状态码/包含文本/JSON 路径),给 agent 做接口级自测;结果可断言、可入检查项。

### 4C. 浏览器自动化
- 能力:navigate / DOM snapshot / click / fill / hover / scroll / **截图与录屏回传(多模态)** / 控制台监听。
- 引擎按需拉起,单实例复用;内嵌预览与自动化共用同一页面会话(agent 点过的效果,人刷新即可复看)。
- 每次验证产出:操作序列 + 截图/录屏 + 控制台增量,挂在工具卡片里可回放。

### 4D. 测试运行器
- **diff 智能选测**:按 git diff 文件集映射关联用例子集(如 12/48),全量回归仅在该子集失败时升级触发。
- 结果结构化:每用例 状态/耗时/失败详情(期望 vs 实际),失败详情带「问 agent」。

### 4E. 检查项(验证沉淀为项目资产)
- 检查项 = 可复执行的验收断言,两类:**项目资产**(存入 `.jide/checks/`,跨会话复用、diff 命中自动带上)与**临时**(仅本次)。
- agent 完成任务须给出检查项执行结果;用户可通过检查项一键复验。

### 4F. 人侧运行与预览
- **运行三档**(顶栏统一入口):
  ① **Agent 自测**——后台静默跑 选测+浏览器断言,不打扰当前视图,结果以徽标+摘要汇报;
  ② **人侧运行 + 预览**——打开内嵌预览,与 agent 共用 dev server 与引擎;
  ③ **调试(CDP 后门)**——附着 CDP;断点调试器为非目标,仅保留协议后门。
- **错误一键问 agent**:终端错误行、测试失败详情、预览控制台异常均可一键把上下文(文件:行、期望/实际)送入对话。

**工具协议表**(agent 侧;详细 schema 归技术设计):

| 工具 | 关键参数 | 返回要点 | 失败语义 |
|---|---|---|---|
| dev_server.ensure | workspace, mode | 状态+URL+探测模式 | 启动超时→错误+日志尾 |
| http.probe | url, expect | 命中与否+实际值 | 断言失败≠工具失败 |
| browser.navigate / click / fill | url/选择器/值 | snapshot+截图引用 | 元素不存在→可重试错误 |
| browser.capture | kind=shot/record | 媒体引用(多模态回传) | 引擎未起→自动拉起 |
| test.run | scope=diff/all | 用例结果列表 | 用例失败≠工具失败 |
| checks.verify | ids | 逐项通过/失败 | 失败附证据链接 |

**验收故事**(见原型演示「修复购物车总额浮点 bug」):
1. *全闭环*:用户一句话 → 计划 5 步推进(自动提交)→ diff 双全文 → 选测 12/48 首轮失败 → 修断言 → 12/12 → 浏览器实操(点击+截图比对 ¥89.70)→ 检查项 4/4 沉淀 → 记忆建议卡片 → 评审通过并入主线。
2. *遗留错误*:终端一行昨天遗留的渲染错误,点「问 agent」→ 上下文芯片(错误文本+来源)入对话,agent 判定「已修复,系归档记录」。
3. *三档*:用户正在写代码,切「Agent 自测」档,视图不被打断,状态栏徽标告知 12/12。

## 5. 记忆域(差异化核心)

**选型对比**(结论:**文件式**胜出):

| 方案 | 优点 | 致命伤 |
|---|---|---|
| 向量库检索 | 语义召回 | 黑盒不可审改;嵌入式库与「轻量」冲突 |
| 结构化 DB | 查询强 | 用户不可直接阅读/编辑;同步麻烦 |
| **文件式**(胜) | 用户可读可改可进 git;冲突即文本 diff;零运行时 | 需自管 token 预算 → 用注入策略解决 |

**作用域 × 类型模型**:

| 作用域 | 路径 | 内容类型 | 谁写 |
|---|---|---|---|
| 项目层 | `.memory/project/*.md` | 框架命令/约定/坑 | 建议卡片+初始导入 |
| 用户层 | `.memory/user/*.md` | 用户偏好与纠正 | 建议卡片(需更谨慎) |
| 会话层 | 会话内临时 | 本会话工作集 | 自动,不落盘 |
| 边界 | `AGENTS.md` | 手写规则 | **仅用户手写**,记忆系统只读不写 |

**记忆文件格式**:每条记忆 = `- 内容`(一行一事);文件头 front-matter 记 来源(会话/建议卡片/初始导入)与最近命中时间。

**生命周期**:
- **写入四通道**:①会话结束沉淀(agent 提炼);②**建议卡片**(任务完成时在对话内弹卡:拟写入路径+内容,用户 采纳/忽略/改后采纳——默认不静默写);③用户手编(外部编辑器改 `.memory/`,热加载);④**任务经历**(P3.4 系统任务沉淀:任务卡终态自动写 `<项目根>/.memory/project/experience.md`,一行一事 `[时间] 结论 · 来源 · 标题:摘要`,插最前上限 100 条,不走建议卡——系统记录非 agent 主张;写在项目根防随 worktree 清理丢失)。
- **三级召回**:注入(必带,预算内)→ 关键词命中(预算外补充)→ 显式引用(@记忆名)。
- **冲突与遗忘(整理)**:预算接近上限(如 ≥95%)提示;「整理」动作合并重复、淘汰过时(以最近命中时间为准),给出前后对照。

**注入策略(经历层加入后 ~2.3K)**:

| 层 | 预算 | 内容 |
|---|---|---|
| 项目层摘要 | ~1.2K | 命令、约定、高频坑(压缩后;不含 experience.md) |
| 经历层 | ~0.3K | 近期任务与结果(跨周/月任务上下文恢复) |
| 用户层摘要 | ~0.4K | 偏好与纠正 |
| 会话层 | ~0.4K | 当前任务上下文 |

**验收故事**:
1. *采纳与预算*:任务完成 → 建议卡片(「金额用分单位整数,断言写字面量」)→ 采纳 → 注入预算 1.8K→1.95K,接近上限提示 → 点「整理」合并 3 条重复反馈回落 1.6K。
2. *召回生效*:新开会话,agent 开口即用 `pnpm test` 与 vitest 术语,不试错——项目层注入命中;用户问「为什么不用 jest」,agent 引用 conventions.md 条目作答。

## 6. 其他模块要点

- **会话**:对话是内容区的一个**页签**(ThinkRail 式),非侧栏;会话随工作区隔离;agent 流式输出期间驻留对话页签,仅在关键节点(编辑完成→diff、浏览器验证→预览)短暂跳转后自动返回;后台变更的页签打绿点。
- **编辑**:轻量代码编辑(语法高亮/编辑/滚动定位;不引全量语言服务,选型见 `tech-stack.md`,组件须可替换);大文件性能预算见技术设计。
- **git diff**:**双全文模型**(左=HEAD 全文,右=工作区全文,非增量 patch 流);呈现为 IDEA 经典款:词级高亮、变更间导航、中缝方向应用(»/«)、变更定位条、未更改行折叠。
- **Git 呈现**:顶栏**分离状态条**(项目 | 工作区 | 分支 | 远程 ↓n)+ 独立操作按钮(同步 / 拉取请求);变更明细与**图形化提交记录**(点线图+短哈希+分支标签+日期分组,自动提交标注「Agent · 计划步骤 N」)在左侧源代码管理面板。
- **终端**:分组随工作区;错误行「问 agent」(实现选型见 `tech-stack.md`)。
- **计划与评审**:计划 = 当前任务步骤清单(右侧工作流面板,进行中带 n/5 徽标);评审队列 = 自动提交/记忆建议/检查项结果的**人工门禁**(通过/追问/看 diff),通过后方可并入主线(W5/W6)。
- **UI 布局骨架**(原型冻结):左侧图标菜单(文件/搜索/Git/记忆)+左面板 | 内容区页签(Agent 对话默认) | 右侧工作流停靠面板(计划/评审)+最右窄菜单;底部 终端/测试/检查项;状态栏(dev 状态、agent 状态、记忆预算、信任)。

## 7. 架构约束

1. **pi 于壳主进程内运行**(ThinkRail 同构);会话必须**可中断/可重建**,并预留拆分为独立子进程的接缝(崩溃隔离的后手)。
2. **类型化 contracts 协议**:壳/宿主/UI 之间一切消息走版本化类型协议;协议三原则——可枚举(工具/事件全量声明)、可演化(版本协商)、可回放(事件流即日志)。
3. **状态三分**:UI 态(可弃)、会话态(pi 持有)、项目态(文件/git,唯一事实源);崩溃恢复 = 重放 UI 态 + 重连会话。
4. **凭据零留存**:模型密钥仅存系统凭据库;任何日志/记忆/回放不得含凭据。
5. **凭据与命令安全**:未信任项目(见 W1)前 agent 无命令执行权;危险命令(删除、推送等)默认需确认,可按项目配置豁免。

## 8. 非目标(明确不做)

| 非目标 | 理由与后门 |
|---|---|
| 断点调试器 | 体积与收益不匹配;保留 CDP 后门(运行三档之③) |
| spec-graph(规格图) | 复杂度高;用「计划步骤 + SPEC 式检查项」替代 |
| 账号体系/云端同步 | 单机优先;记忆走 git 即可同步 |
| 全量 LSP | 轻量高亮编辑够用;后续按需加语言服务 |
| 插件市场 | 先做 jide-ui 内建能力;扩展 API 留内部接口 |

## 9. 里程碑

| 里程碑 | 范围 | 验收标准(可勾选) |
|---|---|---|
| **M1 骨架** | 壳出包 + contracts + pi 会话 | □ Windows 打包冒烟通过 □ UI↔宿主↔pi 一条消息全链路 □ 会话可中断/重建 □ 构建工具链与 CI 就位 |
| **M2 IDE 基面** | 工作区+编辑+终端+对话+计划 | □ 信任门生效 □ worktree 创建/切换,上下文原子换入 □ 编辑器打开 10MB 文件不卡 □ 终端压测不掉帧 □ 对话页签流式渲染 □ 计划步骤自动提交(仅隔离区) |
| **M3 测试闭环** | 测试域全量(4A–4F) | □ 就绪探测三模式 □ 智能选测 12/48 级别响应 <5s □ 浏览器点击+截图回传 □ 检查项沉淀与复验 □ 运行三档 □ 错误一键问 agent □ 评审队列门禁合并 |
| **M4 记忆** | 记忆域全量 | □ 建议卡片三动作 □ 三级注入 ≤2K □ 整理合并可回退 □ AGENTS.md 边界只读 □ 新会话召回命中(验收故事 5.2) |

## 10. 风险

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 壳选型(见 tech-stack)Windows 成熟度不足 | M1 前置打包冒烟(spike#0);不通过则阻塞重估 |
| R2 | pi 进程内卡死拖住主进程 | 会话可中断/重建;预留子进程拆分接缝 |
| R3 | 浏览器引擎重量(内存/启动) | 按需拉起、单实例复用、闲置自动回收 |
| R4 | Windows 子进程回收不可靠(dev/浏览器残留) | 统一进程树清理并纳入崩溃用例测试 |
| R5 | 记忆 token 预算超限/内容腐化 | 预算水位提示+整理动作;一切记忆可 git 回滚 |
